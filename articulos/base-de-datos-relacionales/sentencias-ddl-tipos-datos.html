Sentencias DDL y Tipos de Datos en SQL Server

Publicado: Abril 2026 • Lectura: 15 min

Introducción

Si querés trabajar profesionalmente con bases de datos en SQL Server, necesitás dominar dos cosas fundamentales: las sentencias DDL (Data Definition Language) y los tipos de datos. Las sentencias DDL te permiten crear y modificar la estructura de tu base de datos, mientras que los tipos de datos definen qué tipo de información podés guardar en cada columna.

En este artículo vamos a ver todo lo que necesitás saber sobre ambos temas, con ejemplos prácticos y casos de uso reales.

¿Qué son las Sentencias DDL?

DDL significa Data Definition Language (Lenguaje de Definición de Datos). Son los comandos que usás para crear, modificar y eliminar la estructura de objetos en la base de datos: tablas, vistas, índices, procedimientos almacenados, etc.

Las tres sentencias DDL principales son:

  • CREATE: Crea nuevos objetos
  • ALTER: Modifica objetos existentes
  • DROP: Elimina objetos

A diferencia de las sentencias DML (SELECT, INSERT, UPDATE, DELETE) que manipulan los datos, las DDL manipulan la estructura.

CREATE - Crear Objetos

El comando CREATE se usa para crear nuevos objetos en la base de datos.

CREATE TABLE - Crear una tabla

Esta es la sentencia DDL más usada. Te permite definir una nueva tabla con sus columnas y restricciones.

Sintaxis básica:

CREATE TABLE nombre_tabla (
    columna1 tipo_dato [restricciones],
    columna2 tipo_dato [restricciones],
    ...
);

Ejemplo completo:

CREATE TABLE Usuarios (
    usuario_id INT PRIMARY KEY IDENTITY(1,1),
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    edad INT CHECK (edad >= 18),
    fecha_registro DATETIME DEFAULT GETDATE(),
    activo BIT DEFAULT 1
);

Explicación de cada parte:

  • usuario_id INT PRIMARY KEY IDENTITY(1,1) - Clave primaria que se auto-incrementa desde 1
  • nombre VARCHAR(100) NOT NULL - Texto hasta 100 caracteres, obligatorio
  • email VARCHAR(150) UNIQUE NOT NULL - Email único y obligatorio
  • edad INT CHECK (edad >= 18) - Número entero, debe ser mayor o igual a 18
  • fecha_registro DATETIME DEFAULT GETDATE() - Fecha/hora, por defecto la actual
  • activo BIT DEFAULT 1 - Booleano (0 o 1), por defecto verdadero

CREATE con claves foráneas

Podés crear relaciones entre tablas usando FOREIGN KEY:

CREATE TABLE Pedidos (
    pedido_id INT PRIMARY KEY IDENTITY(1,1),
    usuario_id INT NOT NULL,
    producto VARCHAR(100) NOT NULL,
    cantidad INT NOT NULL,
    precio_total DECIMAL(10,2) NOT NULL,
    fecha_pedido DATETIME DEFAULT GETDATE(),

    -- Clave foránea que relaciona con la tabla Usuarios
    CONSTRAINT FK_Pedidos_Usuarios
        FOREIGN KEY (usuario_id)
        REFERENCES Usuarios(usuario_id)
        ON DELETE CASCADE
);

ON DELETE CASCADE significa que si eliminás un usuario, todos sus pedidos se borran automáticamente.

CREATE VIEW - Crear una vista

Una vista es como una "tabla virtual" que ejecuta una consulta predefinida:

CREATE VIEW Vista_Pedidos_Activos AS
SELECT
    u.nombre,
    u.email,
    p.producto,
    p.cantidad,
    p.precio_total,
    p.fecha_pedido
FROM Pedidos p
INNER JOIN Usuarios u ON p.usuario_id = u.usuario_id
WHERE u.activo = 1;

Ahora podés consultar la vista como si fuera una tabla:

SELECT * FROM Vista_Pedidos_Activos;

CREATE PROCEDURE - Crear un procedimiento almacenado

Un procedimiento almacenado es código T-SQL que se guarda en la base de datos y podés reutilizar:

CREATE PROCEDURE sp_ObtenerUsuariosPorCiudad
    @ciudad VARCHAR(50)
AS
BEGIN
    SELECT nombre, email, edad
    FROM Usuarios
    WHERE ciudad = @ciudad
    ORDER BY nombre;
END;

Para ejecutarlo:

EXEC sp_ObtenerUsuariosPorCiudad @ciudad = 'Córdoba';

ALTER - Modificar Objetos

ALTER te permite modificar la estructura de objetos existentes sin tener que eliminarlos y recrearlos.

ALTER TABLE - Modificar tabla

Agregar una columna nueva:

ALTER TABLE Usuarios
ADD telefono VARCHAR(20);

Modificar el tipo de dato de una columna:

ALTER TABLE Usuarios
ALTER COLUMN telefono VARCHAR(30);

Eliminar una columna:

ALTER TABLE Usuarios
DROP COLUMN telefono;

Agregar una restricción:

ALTER TABLE Usuarios
ADD CONSTRAINT CK_Edad_Minima CHECK (edad >= 18);

Eliminar una restricción:

ALTER TABLE Usuarios
DROP CONSTRAINT CK_Edad_Minima;

Ejemplo práctico completo

Imaginate que creaste la tabla Usuarios y después te das cuenta que necesitás agregar más campos:

-- Agregar varias columnas de una vez
ALTER TABLE Usuarios
ADD
    ciudad VARCHAR(50),
    pais VARCHAR(50) DEFAULT 'Argentina',
    telefono VARCHAR(20),
    foto_perfil VARCHAR(255);

DROP - Eliminar Objetos

DROP elimina permanentemente objetos de la base de datos. ¡OJO! Esta operación es irreversible.

DROP TABLE - Eliminar tabla

DROP TABLE Pedidos;

⚠️ Advertencia: Si intentás eliminar una tabla que tiene relaciones de clave foránea, SQL Server te va a dar un error. Primero tenés que eliminar las restricciones de clave foránea o las tablas relacionadas.

DROP con IF EXISTS (SQL Server 2016+)

Para evitar errores si el objeto no existe:

DROP TABLE IF EXISTS Temporal;

DROP VIEW, PROCEDURE, INDEX

-- Eliminar vista
DROP VIEW Vista_Pedidos_Activos;

-- Eliminar procedimiento almacenado
DROP PROCEDURE sp_ObtenerUsuariosPorCiudad;

-- Eliminar índice
DROP INDEX IX_Usuarios_Email ON Usuarios;

Tipos de Datos en SQL Server

Los tipos de datos definen qué clase de información podés guardar en cada columna. Elegir el tipo de dato correcto es crucial para optimizar el rendimiento y el espacio de almacenamiento.

1. Tipos de Datos Numéricos Enteros

Se usan para guardar números sin decimales.

Tipo Rango Tamaño Uso Común
TINYINT 0 a 255 1 byte Edades, cantidades pequeñas
SMALLINT -32,768 a 32,767 2 bytes Años, números medianos
INT -2,147,483,648 a 2,147,483,647 4 bytes IDs, cantidades grandes
BIGINT -9,223,372,036,854,775,808 a 9,223,372,036,854,775,807 8 bytes Números gigantes (ej: saldos bancarios)

Ejemplo:

CREATE TABLE Productos (
    producto_id INT PRIMARY KEY,
    stock SMALLINT,
    edad_minima TINYINT,
    ventas_totales BIGINT
);

2. Tipos de Datos Decimales

Se usan para números con decimales.

Tipo Precisión Uso Común
DECIMAL(p,s) p = total de dígitos
s = decimales		 Precios, salarios (precisión exacta)
NUMERIC Igual que DECIMAL Sinónimo de DECIMAL
FLOAT Aproximada Cálculos científicos (puede perder precisión)
REAL Aproximada (menor que FLOAT) Similar a FLOAT pero menos preciso

⚠️ Importante: Para dinero y precios, SIEMPRE usá DECIMAL o el tipo MONEY. Nunca uses FLOAT porque puede generar errores de redondeo.

Ejemplo:

CREATE TABLE Productos (
    precio DECIMAL(10,2),  -- Hasta 99,999,999.99
    descuento DECIMAL(5,2), -- Hasta 999.99 (ej: 15.50%)
    peso FLOAT              -- 1.234567 kg (precisión no crítica)
);

3. Tipos de Datos de Caracteres (Texto)

Tipo Tamaño Máximo Uso Común
CHAR(n) 8,000 caracteres Texto de longitud fija (DNI, códigos)
VARCHAR(n) 8,000 caracteres Texto de longitud variable (nombres, emails)
VARCHAR(MAX) 2 GB Textos muy largos (descripciones, artículos)
NCHAR(n) 4,000 caracteres Unicode, longitud fija (caracteres especiales)
NVARCHAR(n) 4,000 caracteres Unicode, longitud variable (emojis, árabe, chino)
TEXT 2 GB ⚠️ Obsoleto, usar VARCHAR(MAX)

Diferencia entre CHAR y VARCHAR:

  • CHAR(10) siempre ocupa 10 bytes, aunque guardes "Hola" (4 letras). Rellena con espacios.
  • VARCHAR(10) ocupa solo lo necesario. "Hola" = 4 bytes, "Bienvenido" = 10 bytes.

¿Cuándo usar N (NCHAR, NVARCHAR)?

Si necesitás guardar caracteres especiales como emojis 😊, árabe, chino, japonés, usá NVARCHAR. Ocupa el doble de espacio pero soporta Unicode.

Ejemplo:

CREATE TABLE Usuarios (
    dni CHAR(8),               -- Siempre 8 dígitos
    nombre VARCHAR(100),       -- Nombre variable
    biografia VARCHAR(MAX),    -- Texto largo
    mensaje NVARCHAR(500)      -- Puede tener emojis
);

4. Tipos de Datos de Fecha y Hora

Tipo Formato Uso Común
DATE YYYY-MM-DD Solo fecha (ej: 2026-04-05)
TIME HH:MM:SS Solo hora (ej: 14:30:00)
DATETIME YYYY-MM-DD HH:MM:SS Fecha y hora completa
DATETIME2 Más preciso que DATETIME Mejor que DATETIME (recomendado)
SMALLDATETIME Menos preciso (1 minuto) Cuando no necesitás segundos
DATETIMEOFFSET Incluye zona horaria Aplicaciones internacionales

Ejemplo:

CREATE TABLE Eventos (
    fecha_nacimiento DATE,
    hora_entrada TIME,
    fecha_registro DATETIME2 DEFAULT GETDATE(),
    ultima_conexion DATETIMEOFFSET
);

5. Tipos de Datos Binarios

Tipo Tamaño Uso Común
BINARY(n) Hasta 8,000 bytes Datos binarios de longitud fija
VARBINARY(n) Hasta 8,000 bytes Datos binarios de longitud variable
VARBINARY(MAX) Hasta 2 GB Imágenes, PDFs, archivos

⚠️ Recomendación: En general, es mejor guardar archivos grandes (imágenes, PDFs) en el sistema de archivos y solo guardar la ruta en la base de datos, no el archivo completo.

6. Otros Tipos de Datos

Tipo Valores Uso Común
BIT 0, 1 o NULL Booleanos (activo/inactivo, sí/no)
MONEY -922,337,203,685,477.5808 a 922,337,203,685,477.5807 Valores monetarios
UNIQUEIDENTIFIER GUID (36 caracteres) IDs únicos globales
XML Documentos XML Guardar datos XML estructurados
JSON Documentos JSON SQL Server 2016+ (como NVARCHAR)

Ejemplo:

CREATE TABLE Productos (
    activo BIT DEFAULT 1,
    precio MONEY,
    producto_guid UNIQUEIDENTIFIER DEFAULT NEWID(),
    datos_extra XML
);

Buenas Prácticas al Elegir Tipos de Datos

  1. Usá el tipo de dato más pequeño posible: Si sabés que una edad nunca va a ser mayor a 150, usá TINYINT en lugar de INT.
  2. Para dinero, usá DECIMAL o MONEY: Nunca FLOAT (pierde precisión).
  3. Para emails y URLs, usá VARCHAR: Son longitud variable y no necesitás Unicode.
  4. Para nombres de personas, usá NVARCHAR: Puede haber caracteres especiales.
  5. Para fechas nuevas, usá DATETIME2: Es más preciso que DATETIME.
  6. Evitá tipos obsoletos: TEXT, NTEXT, IMAGE → Usá VARCHAR(MAX), NVARCHAR(MAX), VARBINARY(MAX).
  7. Definí siempre la longitud en VARCHAR: VARCHAR(100) es mejor que solo VARCHAR.

Ejemplo Completo: Tabla de E-commerce

Juntando todo lo aprendido, así se vería una tabla profesional:

CREATE TABLE Productos (
    -- ID único auto-incremental
    producto_id INT PRIMARY KEY IDENTITY(1,1),

    -- Código único del producto
    codigo_producto VARCHAR(20) UNIQUE NOT NULL,

    -- Nombre y descripción
    nombre NVARCHAR(200) NOT NULL,
    descripcion NVARCHAR(MAX),

    -- Precios
    precio DECIMAL(10,2) NOT NULL CHECK (precio > 0),
    precio_oferta DECIMAL(10,2),
    descuento_porcentaje DECIMAL(5,2) DEFAULT 0,

    -- Stock
    stock INT NOT NULL DEFAULT 0,
    stock_minimo SMALLINT DEFAULT 10,

    -- Categoría (clave foránea)
    categoria_id INT NOT NULL,

    -- Características
    peso DECIMAL(8,2), -- en kg
    dimensiones VARCHAR(50), -- ej: "30x20x10 cm"
    color NVARCHAR(50),

    -- Estado
    activo BIT DEFAULT 1,
    destacado BIT DEFAULT 0,

    -- Fechas
    fecha_creacion DATETIME2 DEFAULT GETDATE(),
    fecha_modificacion DATETIME2,

    -- Imagen (ruta al archivo)
    imagen_url VARCHAR(255),

    -- Metadatos para SEO
    meta_titulo NVARCHAR(100),
    meta_descripcion NVARCHAR(200),

    -- Relación con tabla Categorias
    CONSTRAINT FK_Productos_Categorias
        FOREIGN KEY (categoria_id)
        REFERENCES Categorias(categoria_id)
);

Conclusión

Las sentencias DDL y los tipos de datos son la base de cualquier base de datos profesional en SQL Server. Dominar estos conceptos te permite:

  • Crear estructuras de bases de datos eficientes y optimizadas
  • Ahorrar espacio de almacenamiento eligiendo tipos de datos adecuados
  • Mejorar el rendimiento de tus consultas
  • Garantizar la integridad de los datos con restricciones apropiadas
  • Modificar estructuras sin perder datos

Recordá siempre planificar bien tu estructura antes de crear las tablas. Es mucho más fácil hacerlo bien desde el principio que tener que modificar todo después cuando ya tenés millones de registros.

En los próximos artículos vamos a ver las sentencias DML (SELECT, INSERT, UPDATE, DELETE) y cómo manipular los datos dentro de estas estructuras que creamos.
