Introducción

Antes de comenzar a crear tablas, insertar registros o realizar consultas con SQL, es necesario contar con un espacio donde toda esa información pueda almacenarse de manera organizada. Ese espacio recibe el nombre de Base de Datos.

Una base de datos puede imaginarse como un gran archivador digital. En una empresa, por ejemplo, existen miles de datos relacionados con clientes, productos, empleados, ventas, proveedores y facturas. Si toda esa información estuviera distribuida en archivos separados o documentos de texto, encontrar un dato específico sería una tarea lenta y propensa a errores.

Los Sistemas Gestores de Bases de Datos (DBMS), como Microsoft SQL Server, solucionan este problema permitiendo almacenar la información de forma estructurada, segura y eficiente.

Sin embargo, antes de crear tablas o cargar información, es necesario crear la base de datos donde se almacenarán todos esos objetos.

Para ello, SQL Server proporciona la sentencia CREATE DATABASE, perteneciente al grupo de instrucciones conocidas como DDL (Data Definition Language).

Esta será la primera sentencia que utilizarás al comenzar prácticamente cualquier proyecto de bases de datos.

¿Qué aprenderás?

En este artículo vas a aprender a utilizar la sentencia CREATE DATABASE de SQL Server para crear una nueva base de datos desde cero.

Al finalizar, vas a poder:

  • Entender qué función cumple CREATE DATABASE.
  • Reconocer la sintaxis básica de la sentencia.
  • Crear una base de datos utilizando T-SQL.
  • Seleccionar una base de datos mediante USE.
  • Comprobar cuál es la base de datos actualmente seleccionada.
  • Consultar las bases de datos disponibles en una instancia de SQL Server.
  • Comprender, a nivel introductorio, qué archivos utiliza SQL Server para almacenar una base de datos.
  • Identificar errores frecuentes al utilizar CREATE DATABASE.
  • Aplicar estos conceptos en situaciones similares a las que aparecen en proyectos reales.

También vas a entender algo fundamental: crear una base de datos no significa que ya tengamos creadas las tablas de nuestro sistema. La creación de las tablas será el siguiente paso y la veremos utilizando CREATE TABLE.

Sintaxis

La forma más sencilla de crear una base de datos en SQL Server es:

CREATE DATABASE nombre_base_de_datos;

Por ejemplo, si queremos crear una base de datos para una biblioteca:

CREATE DATABASE Biblioteca;

Al ejecutar esta sentencia, SQL Server crea una nueva base de datos llamada Biblioteca.

¿Qué significa cada parte?

CREATE DATABASE Biblioteca;
  • CREATE — Indica que queremos crear un nuevo objeto.
  • DATABASE — Especifica que el objeto que queremos crear es una base de datos.
  • Biblioteca — Es el nombre que tendrá la base de datos.
  • ; — Indica el final de la sentencia SQL.

Utilizando GO

Cuando trabajamos con SQL Server Management Studio es habitual encontrar:

CREATE DATABASE Biblioteca;
GO

GO no es una instrucción SQL como CREATE DATABASE o SELECT. Es un separador de lotes reconocido por herramientas como SQL Server Management Studio.

Por ejemplo:

CREATE DATABASE Biblioteca;
GO

USE Biblioteca;
GO

En este caso estamos realizando dos operaciones diferentes:

  1. Crear la base de datos.
  2. Seleccionar la base de datos para trabajar con ella.

CREATE DATABASE y USE no hacen lo mismo

Esta diferencia es muy importante.

CREATE DATABASE crea una base de datos nueva:

CREATE DATABASE Biblioteca;

USE selecciona una base de datos que ya existe:

USE Biblioteca;

Por lo tanto:

CREATE DATABASE Biblioteca;
GO

USE Biblioteca;
GO

significa:

"Creá una base de datos llamada Biblioteca y después seleccioná esa base para trabajar sobre ella."

Explicación

Cuando ejecutamos:

CREATE DATABASE Biblioteca;

estamos creando una nueva base de datos dentro de una instancia de SQL Server.

Una forma sencilla de imaginar la organización es:

Instancia de SQL Server
│
├── Base de datos Biblioteca
│
├── Base de datos SistemaVentas
│
└── Base de datos Universidad

Cada base de datos puede contener diferentes objetos, como tablas, vistas, procedimientos almacenados y otros elementos.

Para empezar, es importante entender esta relación:

Instancia de SQL Server
        ↓
    Base de datos
        ↓
       Tablas
        ↓
Filas y columnas

Una base de datos no es una tabla

Esta es una de las primeras confusiones que suele aparecer cuando se empieza a estudiar SQL.

Una base de datos es el espacio lógico donde se organizan los diferentes objetos que forman parte de un sistema.

Una tabla es uno de esos objetos y se utiliza para almacenar información estructurada.

Por ejemplo, podemos tener:

Biblioteca
│
├── Libros
├── Autores
├── Socios
└── Prestamos

Biblioteca es la base de datos.

Libros, Autores, Socios y Prestamos serían tablas.

Pero si ejecutamos solamente:

CREATE DATABASE Biblioteca;

las tablas anteriores todavía no existen.

Primero creamos la base:

CREATE DATABASE Biblioteca;
GO

Y posteriormente podremos crear las tablas mediante CREATE TABLE.

¿Qué ocurre internamente?

SQL Server necesita almacenar físicamente la información de una base de datos. Para ello utiliza archivos.

A nivel introductorio podemos encontrar principalmente:

  • Archivo .mdf — Es el archivo de datos principal de la base de datos. Contiene información almacenada por SQL Server, incluyendo las estructuras y datos de la base.
  • Archivo .ndf — Son archivos de datos secundarios. Una base de datos puede utilizar archivos secundarios cuando la organización o el tamaño de los datos lo requiere. No es necesario utilizarlos para una base de datos sencilla.
  • Archivo .ldf — Es el archivo de registro de transacciones, conocido como transaction log. SQL Server utiliza este registro para mantener información relacionada con las operaciones realizadas sobre la base de datos y ayudar a mantener la integridad de las transacciones.

Para comenzar a trabajar con CREATE DATABASE no necesitamos configurar manualmente estos archivos. SQL Server puede crear y administrar la configuración básica automáticamente.

Consultar las bases de datos disponibles

Podemos utilizar la vista de sistema sys.databases para consultar las bases de datos disponibles en la instancia:

SELECT name
FROM sys.databases;

El resultado mostrará una lista con los nombres de las bases de datos disponibles.

Por ejemplo:

master
tempdb
model
msdb
Biblioteca

Las primeras bases que aparecen son bases utilizadas internamente por SQL Server.

La base Biblioteca sería la que acabamos de crear nosotros.

¿Cómo saber qué base de datos estoy utilizando?

Podemos utilizar la función DB_NAME():

SELECT DB_NAME() AS BaseDeDatosActual;

Si previamente ejecutamos:

USE Biblioteca;
GO

podemos obtener:

BaseDeDatosActual
-----------------
Biblioteca

Esto resulta especialmente útil cuando estamos trabajando con varias bases de datos y queremos comprobar sobre cuál estamos ejecutando nuestras consultas.

Ejemplo práctico

Vamos a crear una base de datos para una biblioteca desde cero.

Paso 1: crear la base

CREATE DATABASE Biblioteca;
GO

En este momento SQL Server crea la base de datos.

Pero todavía no tenemos tablas.

Paso 2: seleccionar la base

USE Biblioteca;
GO

Ahora indicamos que queremos trabajar dentro de Biblioteca.

Paso 3: comprobar la base actual

Podemos verificarlo mediante:

SELECT DB_NAME() AS BaseDeDatosActual;

El resultado debería indicar:

Biblioteca

Paso 4: consultar las bases disponibles

También podemos comprobar que nuestra base aparece entre las bases de datos de SQL Server:

SELECT name
FROM sys.databases;

De esta manera tenemos un pequeño flujo completo:

CREATE DATABASE Biblioteca;
GO

USE Biblioteca;
GO

SELECT DB_NAME() AS BaseDeDatosActual;

Este es un buen ejemplo para ejecutar mientras estás aprendiendo porque permite ver claramente las tres etapas:

Crear → Seleccionar → Comprobar

Otro ejemplo: sistema de ventas

Imaginemos ahora que estamos desarrollando una aplicación para una empresa que vende productos.

Podríamos comenzar creando:

CREATE DATABASE SistemaVentas;
GO

USE SistemaVentas;
GO

Más adelante, esa base podría contener tablas como:

SistemaVentas
│
├── Clientes
├── Productos
├── Ventas
└── DetalleVenta

Nuevamente, CREATE DATABASE solamente crea la base. Las tablas se crearán posteriormente.

Caso real

Sistema para una biblioteca

Imaginemos que una biblioteca quiere desarrollar un sistema para administrar sus libros y préstamos.

Actualmente necesita almacenar información sobre:

  • Libros.
  • Autores.
  • Socios.
  • Préstamos.

Antes de crear esas estructuras necesitamos un lugar donde almacenarlas.

Comenzamos creando la base:

CREATE DATABASE Biblioteca;
GO

USE Biblioteca;
GO

Conceptualmente, nuestro sistema quedaría organizado de esta manera:

Biblioteca
│
├── Libros
├── Autores
├── Socios
└── Prestamos

Cada una de esas estructuras podría convertirse posteriormente en una tabla.

Por ejemplo, Libros podría almacenar información como el título, ISBN y año de publicación.

Socios podría contener los datos de las personas registradas en la biblioteca.

Prestamos podría registrar qué libro fue prestado, a qué socio y en qué fecha.

Pero todavía no necesitamos preocuparnos por esas tablas.

El primer paso fue crear la base de datos.

En el siguiente artículo veremos cómo crear las tablas utilizando CREATE TABLE.

Buenas prácticas

Aunque crear una base de datos parece sencillo, desde el principio conviene acostumbrarse a escribir scripts claros.

Utilizar nombres descriptivos

No es recomendable utilizar nombres como:

CREATE DATABASE BD1;

Cuando el proyecto crezca, BD1 no nos dice prácticamente nada.

Es mucho más claro utilizar:

CREATE DATABASE SistemaBiblioteca;

El nombre permite identificar rápidamente cuál es la finalidad de la base.

Mantener una convención de nombres

Si trabajamos en un proyecto, conviene definir una forma consistente de nombrar las bases y los objetos.

Por ejemplo:

SistemaBiblioteca
SistemaVentas
SistemaHospital

Lo importante es mantener un criterio coherente durante todo el proyecto.

Evitar nombres innecesariamente complicados

Conviene evitar nombres con espacios o caracteres especiales que puedan dificultar el trabajo posterior.

Es preferible:

CREATE DATABASE SistemaVentas;

antes que utilizar nombres poco claros o difíciles de escribir.

Pensar en el mantenimiento

Un proyecto de bases de datos puede crecer bastante con el tiempo. El nombre que hoy parece obvio debería seguir siendo entendible dentro de varios meses, cuando otras personas tengan que trabajar con el mismo proyecto.

Evitar crear una base que ya existe

Si tenemos un script que podemos ejecutar varias veces, podemos comprobar previamente si la base existe.

Por ejemplo:

IF DB_ID('Biblioteca') IS NULL
BEGIN
    CREATE DATABASE Biblioteca;
END;
GO

DB_ID() permite obtener el identificador de una base de datos a partir de su nombre.

En este caso:

DB_ID('Biblioteca')

devuelve información si la base existe. Si no existe, devuelve NULL.

Por eso podemos utilizar la condición:

IF DB_ID('Biblioteca') IS NULL

para indicar:

"Si Biblioteca no existe, entonces créala."

Este tipo de comprobación resulta especialmente útil en scripts que pueden ejecutarse más de una vez.

Errores comunes

Intentar crear una base que ya existe

Por ejemplo:

CREATE DATABASE Biblioteca;
GO

CREATE DATABASE Biblioteca;
GO

La primera sentencia crea la base. La segunda intenta crear nuevamente una base con el mismo nombre y producirá un error porque Biblioteca ya existe.

Escribir incorrectamente el nombre de la base

Si creamos:

CREATE DATABASE Biblioteca;
GO

pero después escribimos:

USE Bibliotecca;
GO

SQL Server no encontrará una base llamada Bibliotecca.

El nombre correcto es:

USE Biblioteca;
GO

Parece un error pequeño, pero es bastante común cuando se empieza a trabajar con SQL.

Confundir CREATE DATABASE con USE

Otro error frecuente es pensar que USE crea una base de datos.

Esto:

USE Biblioteca;

no crea Biblioteca. La base debe existir previamente.

Para crearla utilizamos:

CREATE DATABASE Biblioteca;

Después podemos seleccionarla:

USE Biblioteca;

Pensar que CREATE DATABASE crea las tablas

Después de ejecutar:

CREATE DATABASE Biblioteca;
GO

podemos tener la impresión de que ya está preparado todo el sistema. Pero todavía no tenemos:

  • Libros
  • Autores
  • Socios
  • Prestamos

Tenemos únicamente la base de datos. Las tablas se crearán mediante CREATE TABLE, que veremos en el siguiente artículo.

Utilizar nombres poco descriptivos

Un nombre como:

CREATE DATABASE BD2;

puede funcionar técnicamente, pero no ayuda a entender el proyecto.

Es preferible:

CREATE DATABASE SistemaBiblioteca;

porque cualquier persona que vea el script puede identificar rápidamente su propósito.

Resumen

CREATE DATABASE es la sentencia que utilizamos en SQL Server para crear una nueva base de datos.

Su sintaxis básica es:

CREATE DATABASE nombre_base_de_datos;

Por ejemplo:

CREATE DATABASE Biblioteca;
GO

Una vez creada, podemos seleccionarla utilizando:

USE Biblioteca;
GO

Es importante recordar que CREATE DATABASE crea la base de datos, pero no crea las tablas de nuestra aplicación.

Podemos consultar las bases disponibles mediante:

SELECT name
FROM sys.databases;

Y podemos comprobar cuál es la base actualmente seleccionada mediante:

SELECT DB_NAME() AS BaseDeDatosActual;

También aprendimos que SQL Server utiliza archivos de datos y de registro para administrar físicamente la información de las bases de datos.

Finalmente, vimos algunas buenas prácticas, errores frecuentes y situaciones reales donde CREATE DATABASE representa el primer paso para construir la estructura de un sistema.

Ahora que ya sabemos crear una base de datos, el siguiente paso es aprender a crear las tablas que almacenarán la información.
