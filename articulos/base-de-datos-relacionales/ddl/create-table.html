Introducción

Cuando trabajamos con una base de datos relacional, necesitamos organizar la información en tablas. Cada tabla permite almacenar datos relacionados con un determinado elemento, como personas, productos, clientes o documentos.

Para definir la estructura de una tabla en SQL utilizamos la sentencia CREATE TABLE. Mediante este comando indicamos cómo se llamará la tabla, qué columnas tendrá y qué tipo de información podrá almacenar cada una.

CREATE TABLE pertenece al grupo de sentencias DDL (Data Definition Language), también conocido como lenguaje de definición de datos. Estas sentencias permiten crear y administrar la estructura de los objetos de una base de datos.

En este artículo vamos a trabajar con ejemplos orientados a SQL Server. Primero crearemos una tabla sencilla y después veremos cómo establecer una relación entre dos tablas mediante una clave primaria y una clave foránea.

¿Qué aprenderás?

Al terminar esta guía vas a poder:

  • Comprender para qué sirve la sentencia CREATE TABLE.
  • Reconocer la estructura básica de una instrucción para crear tablas.
  • Definir columnas y seleccionar sus tipos de datos.
  • Comprender la diferencia entre NULL y NOT NULL.
  • Utilizar IDENTITY para generar valores incrementales.
  • Definir restricciones mediante CONSTRAINT.
  • Establecer claves primarias y claves foráneas.
  • Crear dos tablas relacionadas respetando el orden de creación.

Sintaxis de CREATE TABLE

La sentencia CREATE TABLE comienza con el nombre de la tabla que queremos crear. A continuación, entre paréntesis, se especifican sus columnas, tipos de datos y las restricciones correspondientes.

Una estructura general simplificada es la siguiente:

CREATE TABLE nombre_tabla (
    nombre_columna1 tipo_dato,
    nombre_columna2 tipo_dato,
    nombre_columna3 tipo_dato
);

Por ejemplo, si queremos crear una tabla llamada tipos_dni, podemos definir una columna para identificar cada tipo de documento y otra para guardar su descripción.

La estructura también permite incorporar restricciones. Estas se utilizan para establecer condiciones sobre los datos y definir relaciones entre tablas. 

CREATE TABLE nombre_tabla (
    nombre_columna tipo_dato,
    CONSTRAINT nombre_restriccion
        PRIMARY KEY (nombre_columna)
);

En las representaciones de sintaxis, los corchetes indican elementos opcionales y la barra vertical representa una alternativa entre distintas opciones.

Explicación de los elementos de CREATE TABLE

1. Nombre de la tabla

Es el identificador que utilizaremos para reconocer la tabla dentro de la base de datos. Conviene elegir nombres que permitan entender qué información almacena.

En el siguiente ejemplo, el nombre de la tabla es tipos_dni:

CREATE TABLE tipos_dni (
    descripcion VARCHAR(15)
);

2. Columnas y tipos de datos

Cada columna representa un dato que queremos almacenar. Al definirla, también debemos indicar su tipo de dato, que determina qué clase de información puede contener.

Algunos ejemplos del material de SQL Server son:

  • INT: permite almacenar números enteros.
  • VARCHAR(n): permite almacenar cadenas de caracteres de longitud variable, hasta el máximo indicado.
  • DATETIME: se utiliza para almacenar valores de fecha y hora.
  • DECIMAL(p,s): permite almacenar números decimales, indicando la precisión total y la cantidad de posiciones decimales.
  • BIT: representa valores de tipo bit.
  • FLOAT: permite representar números aproximados.

Por ejemplo, en VARCHAR(15), el número 15 indica la longitud máxima de caracteres que puede contener esa columna.

En DECIMAL(4,2), el primer número representa la precisión total y el segundo indica cuántas posiciones corresponden a la parte decimal.

3. NULL y NOT NULL

Al definir una columna podemos indicar si admite valores NULL o si debe contener obligatoriamente un valor.

  • NULL: permite que la columna no tenga un valor asignado.
  • NOT NULL: establece que la columna debe tener un valor.

Observá la diferencia en este ejemplo:

CREATE TABLE personas (
    apellido VARCHAR(50) NOT NULL,
    nombre VARCHAR(50) NULL
);

En este caso, el apellido debe tener un valor, mientras que el nombre puede quedar sin completar. Si no se especifica lo contrario, el material indica que los campos pueden admitir NULL.

4. IDENTITY

IDENTITY permite generar valores numéricos incrementales automáticamente. Se define indicando un valor inicial y el incremento que se aplicará. 

id_tipo_doc INT IDENTITY(1,1)

En este caso, el primer valor generado será 1 y los siguientes aumentarán de a 1. Por ejemplo, la secuencia será 1, 2, 3, 4 y así sucesivamente.

Según el material, IDENTITY se utiliza con tipos de datos numéricos y solamente puede definirse una columna de este tipo por tabla.

5. CONSTRAINT

CONSTRAINT permite definir una restricción y asignarle un nombre. Estas restricciones se utilizan para establecer condiciones de integridad sobre los datos almacenados.

Entre las restricciones que trabajaremos se encuentran:

  • PRIMARY KEY: identifica de manera única cada registro de una tabla.
  • FOREIGN KEY: establece una referencia hacia una columna de otra tabla.

Es posible asignar nombres descriptivos a las restricciones. Por ejemplo, pk_persona identifica una clave primaria y fk_persona_tipo_doc identifica una clave foránea.

Ejemplo práctico: crear una tabla de tipos de documento

Vamos a crear una tabla llamada tipos_dni. Su objetivo será almacenar los distintos tipos de documento y asignar un identificador a cada uno. 

CREATE TABLE tipos_dni (
    id_tipo_doc INT IDENTITY(1,1),
    descripcion VARCHAR(15),
    CONSTRAINT pk_tipo_doc PRIMARY KEY (id_tipo_doc)
);

Analicemos qué hace cada parte:

  1. CREATE TABLE tipos_dni: crea una tabla con ese nombre.
  2. id_tipo_doc INT: define una columna de números enteros.
  3. IDENTITY(1,1): genera identificadores incrementales a partir de 1.
  4. descripcion VARCHAR(15): permite almacenar una descripción de hasta 15 caracteres.
  5. CONSTRAINT pk_tipo_doc: asigna un nombre a la restricción.
  6. PRIMARY KEY (id_tipo_doc): establece la columna identificadora como clave primaria.

La clave primaria permite identificar cada registro de forma única. En este ejemplo, la columna id_tipo_doc cumple esa función.

Una vez creada la tabla, podemos utilizarla como referencia desde otra tabla. Esto nos permite representar relaciones entre distintos conjuntos de información.

Caso práctico: crear dos tablas relacionadas

Ahora vamos a desarrollar un ejemplo más completo. Imaginemos una base de datos que necesita almacenar información de personas y el tipo de documento que utiliza cada una.

Para organizar estos datos vamos a utilizar dos tablas:

  • tipos_dni: almacena los tipos de documento disponibles.
  • personas: almacena los datos personales y el tipo de documento asociado.

Paso 1. Crear la tabla tipos_dni

Primero debemos crear la tabla que contendrá los tipos de documento. Su identificador será la clave primaria. 

CREATE TABLE tipos_dni (
    id_tipo_doc INT IDENTITY(1,1),
    descripcion VARCHAR(15),
    CONSTRAINT pk_tipo_doc PRIMARY KEY (id_tipo_doc)
);

Paso 2. Crear la tabla personas

Después creamos la tabla personas. Esta contendrá información como el legajo, apellido, nombre, fecha de nacimiento, peso, altura y número de documento. 

CREATE TABLE personas (
    legajo INT,
    apellido VARCHAR(50) NOT NULL,
    nombre VARCHAR(50),
    fecha_nac DATETIME,
    peso DECIMAL(4,2),
    altura DECIMAL(3,2),
    id_tipo_doc INT,
    nro_doc VARCHAR(8),
    CONSTRAINT pk_persona PRIMARY KEY (legajo),
    CONSTRAINT fk_persona_tipo_doc FOREIGN KEY (id_tipo_doc)
        REFERENCES tipos_dni (id_tipo_doc)
);

¿Cómo se relacionan las tablas?

La relación se establece mediante la columna id_tipo_doc. En la tabla tipos_dni, esta columna es la clave primaria. En la tabla personas, se utiliza como clave foránea.

La instrucción FOREIGN KEY indica que la columna de personas referencia a la columna correspondiente de tipos_dni.

De esta manera, ambas tablas quedan relacionadas sin necesidad de repetir la descripción del tipo de documento en cada registro de personas.

¿Por qué debemos crear primero tipos_dni?

El orden de creación es importante porque la tabla personas contiene una clave foránea que referencia a tipos_dni. Por eso, primero debe existir la tabla referenciada y luego podemos crear la tabla que establece esa relación.

Este ejemplo muestra cómo CREATE TABLE no solamente permite definir columnas, sino también establecer las restricciones necesarias para organizar la información entre diferentes tablas.

Buenas prácticas al utilizar CREATE TABLE

Antes de crear una tabla, conviene revisar cómo estará organizada la información. Algunas decisiones tomadas en esta etapa determinan la estructura que tendrá la base de datos.

  • Elegir nombres descriptivos: utilizar nombres que permitan reconocer el propósito de cada tabla, columna y restricción.
  • Seleccionar el tipo de dato adecuado: definir cada columna según la información que necesita almacenar.
  • Identificar la clave primaria: determinar qué columna permitirá identificar de manera única cada registro.
  • Revisar los valores NULL: decidir qué columnas pueden quedar sin información y cuáles deben ser obligatorias.
  • Definir las relaciones: identificar qué tablas necesitan referenciar a otras mediante claves foráneas.
  • Respetar el orden de creación: crear primero las tablas que serán referenciadas por otras.

Errores comunes al crear tablas

Al comenzar a trabajar con CREATE TABLE, es posible cometer errores al definir columnas, restricciones o relaciones. Estos son algunos puntos que conviene revisar:

1. No definir correctamente los tipos de datos

Cada columna debe tener un tipo de dato acorde con la información que almacenará. Por ejemplo, utilizar INT para un identificador numérico y VARCHAR para una descripción de texto.

2. Confundir NULL con NOT NULL

Si una columna se define como NOT NULL, debe contener un valor. Si se necesita permitir que quede sin información, hay que contemplar esa condición al definirla.

3. No establecer una clave primaria

La clave primaria permite identificar de manera única los registros de una tabla. Es importante determinar qué columna cumplirá esa función al diseñar su estructura.

4. Referenciar una tabla que todavía no fue creada

Si una tabla contiene una clave foránea que apunta a otra, primero debe existir la tabla referenciada. En el ejemplo anterior, por eso creamos tipos_dni antes que personas.

5. No separar correctamente los elementos

Las columnas y restricciones deben estar separadas correctamente mediante comas. Al escribir la sentencia, revisá también que los paréntesis estén completos y que los nombres de las columnas coincidan con los definidos.

Ejercicios propuestos

Ahora que conocés la estructura de CREATE TABLE, es momento de poner en práctica los conceptos. Intentá resolver los siguientes ejercicios antes de consultar las respuestas.

Ejercicio 1: crear una tabla sencilla

Creá una tabla llamada productos que tenga las siguientes columnas:

  • id_producto: número entero.
  • descripcion: texto de hasta 40 caracteres.
  • precio: número decimal con cuatro posiciones de precisión total y dos decimales.

Objetivo: practicar la definición de columnas y tipos de datos.

Ejercicio 2: utilizar IDENTITY

Modificá la estructura del ejercicio anterior para que id_producto genere valores automáticamente comenzando en 1 e incrementándose de a 1.

Objetivo: comprender el funcionamiento de IDENTITY.

Ejercicio 3: establecer una clave primaria

Definí una restricción llamada pk_producto para establecer id_producto como clave primaria.

Objetivo: practicar el uso de CONSTRAINT y PRIMARY KEY.

Ejercicio 4: crear dos tablas relacionadas

Creá dos tablas: categorias y productos. La primera debe tener un identificador y una descripción. La segunda debe incluir un identificador propio y una columna para referenciar la categoría correspondiente.

Definí una clave primaria en cada tabla y una clave foránea en productos que haga referencia al identificador de categorias.

Objetivo: aplicar PRIMARY KEY, FOREIGN KEY y comprender el orden de creación de las tablas.

Resumen: lo que tenés que recordar

CREATE TABLE es una sentencia DDL utilizada para crear tablas y definir su estructura dentro de una base de datos.

Los conceptos principales de esta guía son:

  • CREATE TABLE: crea una nueva tabla.
  • Columnas: representan los datos que se almacenarán.
  • Tipos de datos: determinan qué clase de información admite cada columna.
  • NULL y NOT NULL: indican si una columna puede quedar sin valor.
  • IDENTITY: genera valores numéricos incrementales.
  • CONSTRAINT: permite definir restricciones con nombre.
  • PRIMARY KEY: identifica de manera única los registros.
  • FOREIGN KEY: permite establecer referencias entre tablas.

La mejor manera de aprender CREATE TABLE es practicar con diferentes estructuras. Empezá creando tablas sencillas y después incorporá restricciones y relaciones, como hicimos con los ejemplos de tipos_dni y personas.

¿Qué sigue después de CREATE TABLE?

Una vez que aprendiste a crear tablas, el siguiente paso es conocer cómo modificar su estructura. Para eso existe ALTER TABLE, una sentencia que permite agregar, eliminar o modificar columnas y restricciones de una tabla existente.
